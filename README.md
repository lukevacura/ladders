# ladde-rs

## The matrix profile

Slide a window of length `m` along a time series. Each window is a *subsequence*. A
subsequence's matrix profile value is its z-normalized Euclidean distance to its nearest
neighbor, so shape matters and offset and amplitude do not. Its matrix profile index is where
that neighbor sits. Matches within `⌈m/4⌉` of the subsequence itself are excluded.

- **Motifs:** the lowest values mark patterns that repeat.
- **Discords:** the highest values mark subsequences unlike anything else, which are often
  anomalies.
- **Regime changes:** where nearest-neighbor links stop crossing a point in time, the series has
  changed behavior.
- **Pattern search:** the distance from a known shape to every subsequence shows where it occurs.

The **left** matrix profile allows only earlier neighbors. Its entry at time `t` depends only on
samples up to `t` and never changes afterwards, so it can be computed live and is safe to use in a
backtest.

For more information, see [The UCR Matrix Profile Page](https://www.cs.ucr.edu/~eamonn/MatrixProfile.html).

## Features

- **Exact and reproducible.** Values are counted on a tick grid you choose (for example `0.01` for
  prices), and every result is identical bit for bit across runs, thread counts, machines, batch
  and stream, and Python and Rust.
- **Streaming.** A growing stream searches all history. A bounded stream searches the last `w`
  samples with fixed memory and a fixed cost per sample. Streams can be checkpointed and restored.
- **Batch.** The left and two-sided profiles, AB-joins between two series, and the k nearest
  neighbors per subsequence, on any number of threads.
- **Both distances.** Z-normalized (shape) and non-normalized (STUMPY's `aamp`, level matters).
- **Real-world data.** Gaps (`NaN`, `±inf`), flat stretches and far-off misprints are accepted.
  Subsequences containing gaps get no match rather than a `NaN`.
- **Streaming analytics.** Running top-k discords, a library of patterns scored on every new
  sample, and regime detection (FLOSS).
- **STUMPY compatible.** The same exclusion zone, constant-subsequence rule and distances, and
  `ladders.stumpy` covers nearly all of STUMPY 1.14.1's API.
- **Errors, not silent changes.** No input panics, and an argument STUMPY would silently clip or
  round raises an error naming the value that gets STUMPY's behavior explicitly.

## Exactness

Each sample becomes an integer number of ticks at a scale, and every distance and comparison is
computed exactly on those integers. Neighbors are ranked on exact distances, and ties go to the
smaller index.

- **Data on a grid** (prices in cents, integer sensor readings, fixed-decimal data) is not
  rounded, so the result is exactly right for the input.
- **Plain doubles** get, by default, the finest power-of-two scale at which every window stays
  exact (about seven significant digits at `m = 64`). The result is exact for those values. Two
  neighbors closer than that resolution may rank in a different order than a float64 library's.
  `scale="finest"`, or an explicit scale, gives finer resolution at some cost in speed.

## How it works

### The formula

For windows `a` and `b` of length `m`, with means `μ`, standard deviations `σ` and correlation `ρ`,
the z-normalized distance is

```
d²(a, b) = 2m (1 − ρ),    ρ = (a·b − m μ_a μ_b) / (m σ_a σ_b)
```

so ranking neighbors is ranking correlations. Sums, variances and the dot product `a·b` are exact
integers on the tick grid. The correlation is the only floating-point step, and each operation in
it is correctly rounded.

**The skip rule:** a block of pairs is left uncomputed only when a proved lower bound places every
pair in it behind the current k-th best of every row and column it could enter, by distance and
then by smaller index. No result and no tie can change, so skipping never alters a bit.

### The algorithm

- **Rolling diagonals.** The dot product rolls along each diagonal: the next value is the last one,
  minus one product, plus one product, in wrapping 64-bit integers. Because that is exact, a
  diagonal restarted from a full product holds the same bits as one that rolled there.
- **Tiles.** Work is cut into tiles of diagonals and bands of rows. Each row keeps its best k and
  merges them in a fixed order, so the thread count never changes a result.
- **Narrow lanes when safe.** A tile runs on 32-bit lanes where a check proves the products fit,
  and on 64-bit lanes otherwise. Windows whose variance passes 64-bit range are ranked on an exact
  cold path.
- **The ladder.** For long windows, each band bounds its pairs from averaged windows in blocks of
  256, then 64, then 16 slots. Only pairs that no layer rules out are computed.
- **Rising floors.** Each range is judged against the floors the ranges before it raised, so the
  bounds tighten as the pass goes.
- **The constant class.** A pair with a constant window has a fixed distance and ties go to the
  smaller index, so a row needs only its first few such pairs.
- **Motif-only mode** keeps one floor for the whole series, so it skips far more and still returns
  the same pair the full profile holds.
- **Streams** compare each new window with the past along the same exact arithmetic, so a stream
  and a batch call give identical bits.

## Testing

Accurate and consistent are checked separately.

- **Exact references.** Results are compared with an arbitrary-precision implementation that ranks
  by exact rationals and shares no code with the fast paths. A second reference, with no width
  limit, covers windows whose variance passes 64-bit range.
- **Every route.** The checks cover every engine, every forced code path, several thread counts
  and tile shapes, and tie-heavy, gappy and outlier series.
- **Concurrency and memory.** The loom and Shuttle model checkers explore thread interleavings, and
  Miri checks for undefined behavior.
- **Bit-for-bit consistency.** Hashes of a fixed output corpus must match across builds and CPUs.
  An x86_64 machine with AVX2 matched the Apple silicon reference on all 4,720 lines.

## Examples

### Python

```python
import numpy as np
import ladders

prices = np.round(100 + np.cumsum(np.random.default_rng(0).normal(0, 0.05, 10_000)), 2)

# The left matrix profile of a whole series, on every core by default.
# Without `scale`, data on a grid gets that grid and plain doubles get the finest exact scale.
res = ladders.left_profile(prices, m=50, scale=0.01)
res.P, res.I, res.scale

# Two-sided (P, I, left_I, right_I); k=3 keeps three neighbors.
two_sided = ladders.matrix_profile(prices, m=50, scale=0.01, k=3)

# Join two series, and the non-normalized profile.
joined = ladders.ab_join(prices[:5_000], prices[5_000:], m=50, scale_a=0.01, scale_b=0.01)
raw = ladders.aamp(prices, m=50, scale=0.01)

# Streaming, one sample at a time.
stream = ladders.GrowingStream(m=50, scale=0.01)
for x in prices:
    result = stream.update(x)        # None until the first subsequence is complete
    if result is not None:
        neighbor, distance = result  # neighbor is -1 when there is no earlier match yet

# Bounded: search only the last 2,000 samples.
bounded = ladders.BoundedStream(m=50, w=2_000, scale=0.01)
neighbors, distances = bounded.update_many(prices)

# Save a stream and pick it up later.
restored = ladders.GrowingStream.restore(stream.checkpoint())

# Streaming discords, pattern matching and regime detection.
discords = ladders.DiscordStream(m=50, k=5, scale=0.01)
discords.update_many(prices)
discords.top()                       # [(index, distance), ...]

template_a = prices[200:250]         # any shape of length m
library = ladders.PatternLibrary(m=50, scale=0.01)
dip = library.register(template_a)
scores = ladders.PatternStream(library).update(prices[-1])  # one distance per pattern

floss = ladders.FlossStream(m=50, width=1_000, scale=0.01, w=2_000)
floss.update_many(prices)
floss.min_interior()                 # (position, score) of the likeliest change, or None
```

STUMPY code switches with one line:

```python
import ladders.stumpy as stumpy

mp_ = stumpy.stump(prices, 50)            # an mparray: mp_.P_, mp_.I_, mp_.left_I_, mp_.right_I_
D = stumpy.mass(prices[:50], prices)      # the distance profile
stream = stumpy.stumpi(prices[:1_000], 50)
stream.update(prices[1_000])
stream.P_, stream.left_P_
```

### Rust

```rust
use core::num::NonZeroUsize;
use ladde::{discord::DiscordTracker, quantize::Scale, stream::GrowingStream};

let prices: Vec<f64> = (0..10_000).map(|i| 100.0 + (i as f64 * 0.05).sin()).collect();
let m = NonZeroUsize::new(50).unwrap();
let scale = Scale::new(0.01).unwrap();
let mut stream = GrowingStream::new(m, scale);
let mut discords = DiscordTracker::new(m, 5);

for &x in &prices {
    // update_exact: the nearest earlier neighbor, with its exact distance
    if let Some((row, score)) = stream.update_exact(x) {
        discords.update(row, score);
    }
}
for d in discords.top() {
    println!("subsequence {:?}: distance² {}", d.index().get(), d.squared_distance());
}
```

Pattern matching:

```rust
use ladde::pattern::{PatternLibrary, PatternStream};

let template_a = prices[200..250].to_vec();  // any shape of length m
let mut library = PatternLibrary::new(m, scale);
let head_and_shoulders = library.register(&template_a).unwrap();

let mut matcher = PatternStream::new(library);
for &x in &prices {
    let scores = matcher.push(x);       // one entry per pattern, for the subsequence ending at x
    if scores.is_empty() { continue; }  // the first m - 1 samples complete no subsequence
    let hs = scores[head_and_shoulders.get()].squared_distance();
}
```

Regime detection with FLOSS:

```rust
use ladde::{bounded::BoundedStream, floss::Floss};

let w = NonZeroUsize::new(2_000).unwrap();
let mut stream = BoundedStream::new(m, w, scale).unwrap();
let width = NonZeroUsize::new(1_000).unwrap();
let mut floss = Floss::new(m, width, w.get() - m.get(), m.get(), 5);

for &x in &prices {
    if let Some((row, entry)) = stream.update(x) {
        floss.update(row, entry);
        if let Some((position, score)) = floss.min_interior() {
            // a low score marks a likely regime change at `position` in the window
        }
    }
}
```

## Performance

Measured once, on one machine type (an AWS `c6a.4xlarge`, AMD EPYC 7R13, AVX2), on 2026-11-18,
against STUMPY 1.14.1 and SCAMP (pyscamp 4.0.3, double precision, CPU). Above 1× means this
library was faster.

| Workload | vs STUMPY | vs SCAMP |
|---|---|---|
| Two-sided profile, n = 2^14 to 2^17 | 3.9–11× | 0.97–2.4× |
| Two-sided profile, n = 2^20 and longer real series | 14–87× | 1.1–19.5× |
| AB-join | 4.2–30× | 0.96–6.1× |
| Non-normalized (`aamp`) | 33–49× | (SCAMP has none) |
| Top-k, k = 1 to 16 | 1.9–16× | (SCAMP has none) |
| Stream update | 5.4–148× | (SCAMP has none) |

- **Each range spans many datasets, lengths and thread counts.** [BENCHMARKS.md](BENCHMARKS.md)
  has every row: 120 rows over 202 timed cells, with the method.
- **Against SCAMP it is about even on short windows** and far ahead on long windows over long
  series, where the skip rule applies. SCAMP's GPU path was not measured.

Against nearest neighbors computed in exact arithmetic, on 22,062 rows of short series chosen to
stress exactness (so not an error rate on typical data):

| Engine | Farther neighbor | Near-tie, other neighbor | Differs by convention |
|---|---|---|---|
| This library | 0 | 6 | 0 |
| STUMPY | 11 | 7 | 0 |
| SCAMP | 831 | 7 | 625 |

The farther neighbors are all on a series with gaps and far-off misprints. "Differs by convention"
is not an error: SCAMP treats constant windows and the edge of the exclusion zone differently from
STUMPY, whose rules the comparison follows. [BENCHMARKS.md](BENCHMARKS.md) explains each column,
and [`tools/exact-panel`](tools/exact-panel) reruns it.

## Using it

**Rust.** Add `crates/core` as a git or path dependency. It needs Rust 1.94 or later and is
`no_std` by default.

| Feature | What it adds |
|---|---|
| `std` | Runtime CPU detection, so `x86_64` uses AVX2 when the machine has it |
| `parallel` | Scoped threads for batch work (turns on `std`) |
| `rand` | Lets `scrump` draw its order from any `rand_core::RngCore` |
| `oracle` | The exact reference implementations, for tests and tooling only |

**Python** (3.9 or later). Build a wheel with [maturin](https://www.maturin.rs) and install it:

```sh
maturin build --release -m crates/python/Cargo.toml -o dist
pip install dist/ladders-*.whl
```

**Tests.** `cargo test --workspace --features ladde/std` runs the Rust suite.
`pytest crates/python/tests` runs the Python suite against an installed wheel built with
`--features test-hooks`; it needs numpy, pytest, mpmath and STUMPY 1.14.1. The `scripts/` directory
holds the generators for the constant tables and the STUMPY reference fixtures.
